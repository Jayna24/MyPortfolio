Process Management & CPU Scheduling

Process Management

What is a process?

A process is a running instance of a program.

  • Program: Stored instructions. A program does nothing until it is executed.
  • Process: An active execution with code, data, resources, and an OS record called a process control block.
  • The same program can have several processes. They may share the same code, but each has its own execution state and data.
  • With several processes active, the OS schedules CPU time. Processes can exchange data through interprocess communication (IPC).

Example: Start two instances of the same program. Both use the same executable, but each can be at a different instruction.

Process Management

CPU and I/O bursts

A process typically alternates between computing and performing I/O.

  1. CPUInitialize variables
  2. I/ORead input
  3. CPUCalculate a result
  4. I/OWrite output
  • CPU-bound: Computation dominates, so CPU bursts tend to be longer. Think of a large numerical calculation.
  • I/O-bound: Time is dominated by input or output. Think of a task that frequently waits for disk reads.

Remember: While one process waits for I/O, another ready process can use the CPU.

Process Management

Five process states

New
The OS is creating the process.
Ready
It can run as soon as a CPU is assigned.
Running
Its instructions are executing on a CPU.
Waiting (blocked)
It needs an event such as I/O completion before it can run again.
Terminated
It has finished or has been stopped.

Key distinction: Ready means waiting for the CPU. Blocked means waiting for an event, even when the CPU is idle.

How processes change state

  1. RunningRequests a disk read
  2. WaitingDisk read completes
  3. ReadyScheduler selects it
  4. RunningContinues execution
New → Ready
The OS admits the process.
Ready → Running
The dispatcher hands it the CPU.
Running → Ready
A time slice expires or a higher-priority process preempts it.
Running → Waiting
It requests I/O or blocks on an event.
Waiting → Ready
The event occurs; it may still need to wait for the CPU.
Running → Terminated
It exits or is stopped.

Process Management

Process control block (PCB)

The PCB is the OS record for a process. The process table tracks these records.

Identity
Process ID (PID) and parent or child relationships.
Execution context
Process state, CPU registers, and the program counter for the next instruction.
Scheduling and events
Priority, queue references, and the event a blocked process is waiting for.
Resources
Memory mappings, open files, and I/O information.

Why it matters: Saving the program counter and registers lets a process resume from where it was interrupted.

Process Management

Scheduling queues

Job queue
Holds jobs waiting to be admitted in the textbook model.
Ready queue
Holds runnable processes waiting for CPU time.
Device queue
Holds requests or processes waiting for a particular I/O device.

Follow a process: It enters the ready queue, gets CPU time, and may move to a device queue. When I/O finishes, it rejoins the ready queue.

One way to represent a queue is as a linked list of PCBs, with references to its first and last entries.

CPU Scheduling

When does the scheduler act?

CPU scheduling selects which ready process should run next.

A running process blocks
Choose a ready process, if one exists.
A running process exits
Choose a ready process, if one exists.
A running process is preempted
It returns to the ready queue, and the scheduler selects what runs next.
A blocked process becomes ready
A preemptive policy may switch processes or let the current one continue.

Remember: An I/O completion makes a process ready; it does not guarantee an immediate turn on the CPU.

CPU Scheduling

Scheduler vs. dispatcher

The scheduler chooses. The dispatcher hands over the CPU.

  1. Save the outgoing process's context and load or restore the selected process's context.
  2. Switch to user mode if the selected process is a user process.
  3. Transfer control to the selected process's next instruction, or its entry point if it is starting.

Dispatch latency: The time it takes to stop one process and start or resume another.

CPU Scheduling

What makes a scheduler effective?

Fairness
Give eligible processes a fair share of CPU time.
CPU utilization
Keep the CPU busy for a larger share of elapsed time.
Balanced utilization
Keep CPU and I/O resources productively occupied.
Throughput
Complete more processes per unit of time.
Turnaround time
Minimize the time from arrival to completion.
Waiting time
Minimize the total time spent in the ready queue, not time blocked for I/O.
Response time
Reduce the time from a request to the start of its response.

Trade-off: A policy that improves throughput may not give the quickest response to an interactive request.

CPU Scheduling

Preemptive vs. non-preemptive

Non-preemptive

  • Once selected, a process keeps the CPU until it exits or blocks.
  • Examples: FCFS and non-preemptive shortest job first (SJF).

Preemptive

  • The OS can take back the CPU before the process finishes or blocks.
  • A preempted process returns to the ready queue. Examples: round robin and shortest remaining time next (SRTN).

Remember: A priority-based policy can be preemptive or non-preemptive.

Scheduling Algorithms

First-come, first-served (FCFS)

Give the CPU to the process that has been waiting at the head of the ready queue.

  1. Add arriving or newly unblocked processes to the tail of the ready queue.
  2. When the CPU is free, remove the process at the head and run it.
  3. Continue running that process until it exits or blocks. A new arrival does not interrupt it.

FIFO rule: First in, first out. A long process at the front can make several short processes wait.

Review

Check your understanding

A disk read finishes. Does the waiting process start running immediately?

No. It becomes ready and has to be selected for CPU time.

What information lets an interrupted process resume in the right place?

Its saved program counter and CPU registers are restored as part of the context switch.

Why does P4 wait 23 ms in the FCFS example?

It arrives at 5 ms, but P1, P2, and P3 entered first. P4 starts at 28 ms, so its wait is 28 − 5 = 23 ms.
